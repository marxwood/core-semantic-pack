# Regime Canon gap ledger

**Status:** Exploration ledger / non-canonical

This document separates what the current System Momentum Canon already defines from what the Core Semantic
Pack now carries as an exploratory elaboration.

## Already present in the Canon

The Canon already defines:

- `Regime` as a canonical constraint framework;
- the separation of Regime from KSA, execution, and doctrine;
- the five-Regime default set;
- the five required Regime components;
- explicit Regime switching;
- preservation of applied Regimes in Provenance;
- non-transferability of validity across Regimes;
- contextual validity outcomes;
- invalidation as a trace-preserving event;
- prohibition of silent Regime switching;
- prohibition of Projection-based universalization.

## Added here as exploratory candidates

The Core Pack adds candidate detail for:

- per-Regime admissible Claim classes;
- per-Regime Evidence minimums;
- per-Regime Provenance requirements;
- per-Regime support and contradiction handling;
- per-Regime invalidation triggers;
- candidate escalation paths;
- a complete Regime switch record;
- Domain Pack compatibility declarations;
- comparative evaluation representation;
- conformance fixture shapes.

These details are sourced from the February 2026 Regime exploration and are not represented as already
canonical.

## Questions for the next Canon review

1. Should the Canon enumerate the complete matrices, or only define stronger invariants from which they can
   be derived?
2. Is the candidate escalation graph canonical, derivative, or doctrine-level?
3. Should `Disciplined` be canonically named as the default Regime for coherent systems, or is the current
   wording sufficient?
4. Should independent corroboration be a universal High-Assurance requirement or a doctrine/domain
   specialization?
5. Which fields belong in the canonical Regime switch record?
6. Should Regime outcome vocabulary remain exactly `maintained / contested / invalidated / retired`?
7. How should Canon distinguish comparative evaluation from Regime switching?
8. May an Execution Contract add stricter criteria while preserving the selected Regime identity?
9. What is the exact boundary between a domain Evidence policy and a Core Regime Evidence policy?
10. Does Locked permit explicit reopening only through High-Assurance, or may another target be declared?

## Decision discipline

Until the Canon is updated:

- Core Regime identities and canonical summaries cite the Canon.
- Enumerative matrices remain `exploratory`.
- Domain Packs cannot redefine the five Core Regimes.
- Execution Contracts select, apply, and constrain; they do not author Regime semantics.
- Any future promotion must occur through an explicit Canon amendment.
